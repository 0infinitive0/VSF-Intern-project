Hotel pipeline giải thích

Pipeline này đọc JSON dump từ Agoda và Booking, chuẩn hóa thành mô hình flat theo từng OTA listing, dedupe trong batch, rồi upsert vào PostgreSQL qua ba bảng chính: hotels, rooms, room_prices.

Luồng ETL

Airflow chỉ orchestration, logic thật nằm trong hotel_pipeline.py

DAG booking_agoda_hotel_loader_pipeline bọc từng function pipeline thành PythonOperator, truyền dữ liệu qua XCom, rồi chạy chuỗi cố định: extract >> validate >> normalize >> dedupe >> load_to_postgresql >> quality_check.

01 extract

Đọc source JSON

Load hai file, normalize Unicode NFC, rồi gắn source_platform cho từng record.

02 validate

Chặn lỗi DB sớm

Reject thiếu hotel_id, hotel_name, room id/name hoặc star_rating ngoài 0-5.

03 normalize

Đưa về shape canonical

Map country/city/type, parse ngày, parse room size, parse max guests theo ngữ nghĩa từng OTA.

04 dedupe

Giữ bản mới nhất

Dedupe theo natural key trong batch; bản có scraped_at mới hơn thắng.

05 load

Upsert transaction

Tạo/lấy destination, upsert hotel, room, price trong một transaction; lỗi thì rollback.

06 quality

Ghi report

Tổng hợp validation, dedupe, load stats, hotels by source và sanity issues.

Contract dữ liệu

Đơn vị lưu trữ là OTA listing, không phải khách sạn vật lý duy nhất

hotels

1 dòng = 1 khách sạn theo 1 OTA

Natural key là (source_platform, source_hotel_id). Một khách sạn xuất hiện ở cả Agoda và Booking vẫn là hai dòng.

rooms

Room gắn với hotel row

Room unique theo (hotel_id, source_room_id), nên room id giống nhau ở hai OTA không va nhau.

room_prices

Giá mới nhất theo ngày và package

Unique index dùng room_id, ngày check-in/out, source_url, package_details.

Agoda rooms_available: boolean Booking rooms_available: int ép về boolean Agoda max_guests: người lớn Booking max_guests: tổng khách
Quy tắc chính

Các invariant cần nhớ khi sửa hoặc debug pipeline

Boundary

Không cross-OTA dedupe

Pipeline chỉ loại duplicate cùng source_platform và source_hotel_id. Đây là lựa chọn có chủ ý để chatbot so sánh giá/chính sách giữa OTA.

Validation

Reject trước transaction

Những lỗi có thể làm DB constraint fail được bắt ở validate để không làm abort cả batch trong bước load.

Normalize

Giữ raw context khi dữ liệu không chắc

Bed description, max occupancy raw và source-specific JSON được giữ lại; chỉ parse best-effort các field đủ tin cậy.

Transaction

Load là all-or-rollback

load_hotels_to_db commit sau khi xử lý hết hotels/rooms/prices; exception sẽ rollback và raise lại.

Code map

Nơi đọc khi cần kiểm tra từng phần

Phần File Điểm vào Vai trò
DAG src/airflow/dags/data_pipeline/hotel_dag.py extract_task đến quality_task Định nghĩa Airflow params, XCom keys, task order và schedule manual.
Extract + Validate src/airflow/dags/data_pipeline/hotel_pipeline.py extract_hotels, validate_hotels Đọc JSON, gắn source, loại record có khả năng phá constraint DB.
Normalize src/airflow/dags/data_pipeline/hotel_pipeline.py normalize_hotel, normalize_room Map dữ liệu OTA sang canonical dict để load xuống schema flat.
Dedupe + Load src/airflow/dags/data_pipeline/hotel_pipeline.py dedupe_hotels, load_hotels_to_db Giữ bản mới nhất trong batch và upsert vào PostgreSQL.
Schema scripts/database_schema.sql hotels, rooms, room_prices Định nghĩa uniqueness, foreign keys, CHECK constraints và unique index giá phòng.

Debug nhanh: nếu Airflow task fail ở load_to_postgresql, kiểm tra report/stat của validate trước, vì pipeline cố tình catch constraint-sensitive issues trước khi mở transaction DB.

Test liên quan: src/airflow/tests/test_hotel_pipeline.py cover normalize aliases, validation rejects, within-batch dedupe, cross-OTA non-merge, upsert commit và rollback.
